変更要望: 実装済み・リリース済みで要件（USDM / RDRA）に未反映の 5 件の取り込み（実装契約の正本は docs/AS-BUILT.md。各項目の節を参照）

背景:
次の変更は v1.5.0〜v1.8.0 で実装・リリース済みだが、要件の正本（docs/usdm/latest・docs/rdra/latest）に反映されていない。
実装契約（docs/AS-BUILT.md）を根拠に、要件として取り込む。実装に無い挙動を発明しない。

1. 実行ワークスペース方式（v1.5.0。AS-BUILT §5.7、部分実行との関係は §3.4）
   - 同じシナリオを並走できるよう、run ごとに scenario/ を .stfw/runs/{run_id}/workspace/ へ複製して実行する。
   - 実行時の生成物（evidence/・actual/・result/ 等）は run ワークスペースにだけ生成し、scenario/ の正本には書き込まない。
   - ワークスペースは実行結果ハウスキープ（保存期間）の対象。部分実行も新しいワークスペースで実行される。
2. resume（v1.5.0。AS-BUILT §5.8）
   - --resume で前の run のワークスペース（収集済みエビデンス・実行時の生成物）を引き継いで途中から再開する。
     完了済みの run だけを引き継ぎ元にでき、scenario/ 正本の修正が優先される（正本優先マージ）。
   - 注意（compareRegex。AS-BUILT §4.11.1）: resume は前 run の evidence を引き継ぐため、時刻入りのファイルを出す収集ステップは
     前回のファイルを消してから書く（溜まると compareRegex が名前順で最初の古いファイルを比較する）。
3. run_id の採番規則（v1.6.12。AS-BUILT §5.2・§5.5）
   - 同じ秒に複数の run が始まった場合の採番と、run の並び順（採番時刻 → pid の数値）。詳細は §5.2・§5.5 のとおり。
4. stfw:full へのツール同梱（v1.6.12〜。AS-BUILT §4.8「イメージ同梱版へのフォールバック」・§10.2）
   - stfw:full は外部ツール（k6 / compare-files / logfilter）を /opt/stfw/bundled に同梱し、環境変数 stfw_plugin_bundled_dir で公開する。
   - プラグインは永続キャッシュが無ければ、版が設定と一致する同梱版を使う（stfw plugin install やネットワークなしで実行できる）。
     解決順は「永続キャッシュ → 同梱版 → 未プロビジョニング」。版の上書きはプロジェクト共通設定で行う。
   - 同梱ツールの版は各プラグインの既定設定 config.yml を正とする（現在: k6 v2.4.0 / compare-files v2.2.4 / logfilter v2.0.2）。
5. 既存の要件に残る古い記述の確認
   - 上の 4 件と食い違う既存の USDM / RDRA の記述があれば、AS-BUILT に合わせて更新する。

範囲外（別途、非機能要求・アーキテクチャ側で扱う）:
- CI の脆弱性スキャン（govulncheck / Trivy / 定期チェック）。AS-BUILT §10.4。
